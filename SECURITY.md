# Security policy

CrisisWeave handles crisis and recovery information, so security reports should be treated as potentially safety-sensitive.

## Reporting

Do not publish exploitable vulnerabilities, credentials, private survivor information or operational access details in a public issue.

Report the problem privately to the repository owner through GitHub's private vulnerability reporting feature when available. Include the affected component, reproduction steps, impact and the minimum information necessary to reproduce the issue.

If private vulnerability reporting is unavailable, contact the repository owner privately before disclosing technical details publicly.

## Scope

Useful reports include input-validation bypasses, alert-rule integrity problems, denial-of-service vectors, unsafe data disclosure, dependency or CI supply-chain issues and ways to create misleading or unauthorised alerts.

CrisisWeave is coordination support, not an emergency-dispatch authority. Security fixes must preserve that boundary and should fail closed when uncertainty could create unsafe operational behaviour.
